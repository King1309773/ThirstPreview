# 容器提示兼容修复

目标：修复用户报告的 RS 终端补水行缺失，并让现有提示适应更多遵循 Forge 提示事件的容器。沿用现有水滴图标、数值回退和无“补水：”前缀的显示方式。

## 实际根因

1. 本包 `morerefinedstorage-2.3.2.jar` 的 `GuiGrid` 调用原生物品提示并携带真实物品，但 `RenderUtils.drawTooltipWithSmallText` 的 PostText 高度包含底部小字，行列表不包含底部小字。旧版强制高度恰好等于主行数乘 10，导致提前返回，留下空白预留行。合成预览同样受影响。
2. RS 合成监视器物品详情、Forge 的文字列表入口以及部分 JEI 入口会丢失渲染事件的 ItemStack。生成提示时已有正确数值，绘制时重新查询空 ItemStack 导致空白。

## 修复边界

- 扩展高度允许附加底部区域，保持主行位置与全部行号、溢出、边界和完整性检查；不覆盖或移除 RS 库存底部说明。
- 在原始 ItemTooltipEvent 解析真实物品时，将有符号补水点数作为不可见的格式码快照随所属提示行传递。PostText 从该行读取，不引用“最近物品”全局缓存，不要求容器提供真实 ItemStack。
- 快照随复制、缓存和多提示框交错而保持独立；重复生成仅保留一条所属图标行。对不支持物品和关闭显示的生成事件清理所属旧图标行。
- 保留现有原生纹理、半滴、负值、零值、紧凑大数值、Shift 详情和数值兜底。保持容器原生绘制和换行，不取消 Pre 或用普通提示替换自定义提示。换行后从完整快照首片段读取数值；空间允许时在所属行显示数值，连完整数值也放不下时跳过以免越界。
- 独立实际绘制发现 LWJGL 2 的 glGetFloat 要求至少 16 浮点缓冲区，修复提示状态保护与 HUD 状态保护中的两处四浮点分配。
- 不增加 RS、JEI 或背包模组的必装依赖；不更改补水配置、消费规则和存档。

## 覆盖与限制

覆盖普通箱子、背包、机器槽位等标准容器，以及遵循相同 Forge 主行排版的 RS 普通/无线/便携/大型/合成终端、合成预览和物品详情提示。完全绕过物品提示生成与 Forge 提示事件的界面，以及只显示任务名称的 RS 任务标签不在通用修复范围。

## 验证

先重现 RS 附加底部高度的失败测试；为快照的空物品上下文、复制/缓存/交错、完整整数范围、不可见性、重复行和损坏数据写回归测试。使用实际 RS JAR 的调用路径检查作为辅助证据，运行原有补水/布局/横条测试。交付 1.1.2 测试版，保留未进行游戏内视觉验收的说明。
